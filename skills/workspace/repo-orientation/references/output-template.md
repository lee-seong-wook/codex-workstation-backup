# Repo Orientation Output Template

Use this shape when reporting orientation results.

**Repo Orientation**
- **Snapshot:** purpose, stack, app or library type, monorepo or single project, confidence.
- **What I Checked:** short evidence list, such as `AGENTS.md`, `README`, manifests, entry points, test config.
- **Key Paths:** small table with path, role, and why it matters.
- **How To Work Here:** install, run, test, lint, and build commands found in repo files.
- **Architecture Map:** main runtime flow, boundaries, modules, and data flow when directly supported by evidence.
- **Conventions And Constraints:** local instructions, style patterns, generated or vendor paths to avoid.
- **Likely Next Reads:** 3 to 6 files or directories tied to the user's task.
- **Unknowns / Risks:** missing docs, unclear commands, ambiguous ownership, stale configs, or weak evidence.
- **Next Step:** one concise recommendation, such as continue directly, use `systematic-debugging`, use `brainstorming`, or write a plan.

Keep the result useful for action. Do not list every file or repeat generic framework knowledge unless it explains this repository.
